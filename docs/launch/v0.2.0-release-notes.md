# VectorLedger v0.2.0

VectorLedger 0.2 adds an explicit choice between immediate hard deletion and reversible
scheduled deletion for ACL-aware RAG systems.

## Highlights

- Immediate deletion remains the default.
- Scheduled deletion applies a deny-all ACL, invalidates caches, and records a purge
  deadline before hard deletion.
- Restoring a quarantined document reuses its chunks; restoring after hard deletion
  explicitly requires re-ingestion.
- Signed receipts distinguish `pending_deletion` quarantine from verified `deleted`.
- Qdrant discovery now follows every scroll page instead of stopping at 256 points.
- Redis cache namespaces safely encode tenant and document identifiers.
- Artifact IDs cannot be reassigned across tenant or document lineage.
- The Docker demo covers immediate deletion, scheduled quarantine, and restoration.

## Upgrade notes

The additive `002_scheduled_deletion.sql` migration runs automatically at startup.
Scheduled mode is safe only when all retrieval paths enforce `allowed_principals` and
treat an empty ACL as deny-all. Operators without that guarantee should continue using
the default immediate mode.

```bash
docker pull ghcr.io/mrhello291/vectorledger:0.2.0
```
